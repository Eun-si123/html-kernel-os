# M5-E1 — guarded real CPL3 CPU fault recovery back to live UART shell

**Status:** opt-in x86-64 BIOS QEMU/host UBSan proof PASS, PR #77 merged as `923f353`; subsequent invalid syscall handling PR #78 merged as `881ea55` after exact-head GitHub CI and Gitleaks PASS. This is bounded recovery for a *known active* Ring3 application, not safe execution of arbitrary untrusted code or the full M5-E timer budget.

## Reproduce

```sh
python3 -m unittest tests.test_user_fault_policy tests.test_console_runner -v
python3 scripts/test_m5_user_fault_recovery.py
python3 scripts/build_boot.py --exception-idt --tss-ist --romfs-run-console --user-fault-recover --out build/html-kernel-m5-recovery.iso
# In an Ubuntu interactive terminal with QEMU, GCC and xorriso:
python3 scripts/run_m5_console.py --with-user-program --recover-user-faults
```

The opt-in builder adds *only* in this mode seven additional compiled source programs under immutable ROMFS: `fault-io.hke` (actual Ring3 privileged `OUTB` → CPU #GP error 0), `fault-pf.hke` (actual user read of supervisor virtual address → CPU #PF error 5 on IST2), `fault-ro.hke` (actual user write into protected RO code page → CPU #PF error 7 on IST2), `fault-ud.hke` (actual `UD2` opcode → CPU #UD), `fault-de.hke` (integer divide by zero → CPU #DE), `fault-db.hke` (ICEBP single-byte instruction → #DB), and `fault-bp.hke` (`INT3` → #BP). The valid existing `/apps/hello.hke` remains available, and neither default boot nor M5-D1 builds contain these recovery behaviors.

## Runtime guard and recovery contract

- After real COM1 `run /apps/fault-*.hke`, the guest executes the image in native CPL3 through the existing M5-C1 private CR3 / RO code / RW stack mapping, not a simulated CPU exception. `boot/exception_idt.c` handles **only** guarded vectors 0 (#DE), 1 (#DB), 3 (#BP), 6 (#UD), 13 (#GP), 14 (#PF) when explicitly enabled; all other exceptions and legacy modes remain fail-stop. The user-visible behavior is still `M5_ERR_USER_FAULT`, with a distinct vector marker and six-frame reclaim.
- Before abandoning a task the new pure `boot/user_fault_policy.c` guard verifies expected Ring3 CS/SS, executable RIP interval, user RSP interval, RFLAGS reserved/IOPL/NT/VM restrictions, exact current private CR3 ownership and architectural user error-bit requirements. The caller additionally requires an active selected program, original safe kernel stack/CR3, exactly six owned frames, no previous fault and no completed exit. #PF must have a genuine IST2 stack. *CPL0 faults never access unprovided user RSP/SS fields* and are not accepted as a user fault.
- For a valid active task fault, the existing trusted `htmlk_m4_user_return()` restores the original Limine kernel CR3/main stack; the existing tagged frame registry releases **all six** code, stack and page-table frames on that safe stack. The active shell prints `M5_ERR_USER_FAULT`, then another genuine UART `M5_PROMPT>`. Normal successful user program exit is unchanged.
- `scripts/test_m5_user_fault_recovery.py` boots the real image **three times**, performs all **seven** actual CPU fault/trap paths after the E3-C test expansion, and after **each** executes `/apps/hello.hke` successfully in the same boot. It asserts seven distinct fault markers and seven explicit reclamations per repetition, two IST2 proofs, COM1 output, and clean shell `exit`. Further genuine QEMU scenarios independently mutate HTML source and the standalone user assembly to change their ISO bytes and observed CPU output, check no-input idle and reject invalid builder combinations.
- **Additional M5-E1 syscall isolation:** after strict Ring3 CS/SS, executable RIP, private-stack, current CR3, IOPL and six-frame ownership checks, any unsupported `int 0x80` ID or invalid parameter **terminates only the active user task**. The existing safe kernel CR3/stack restoration and six-frame reclaim path is reused; the UART shell emits `M5_ERR_USER_SYSCALL` and stays interactive. In separate native QEMU builds, both an unknown syscall ID and an invalid numeric argument are executed as real user instructions in `run /apps/hello.hke`; each is preceded and followed by execution of an independent valid `/good.hke`, a working `help`, and clean shell `exit`. A process syscall protocol violation is distinguished from a recognized CPU #DE/#DB/#BP/#GP/#PF/#UD (reported as `M5_ERR_USER_FAULT`). Standalone older M4-C1 and M5-C1 probes retain their original fail-stop syscall behavior. This is **not a full syscall ABI** and does not accept arbitrary user pointers.
- **M5-E3-B extended trap gate (local branch):** actual QEMU first reproduced that an otherwise valid CPL3 integer divide-by-zero terminated the *entire* kernel with QEMU exit 45 and `M3_EXCEPTION V=00`. A new opt-in guarded recovery path retires **only the offending user application** on #DE, #DB (ICEBP) and #BP (INT3). #BP needs an actual architectural IDT vector-3 **DPL3 interrupt gate**, switched on exclusively with `HTMLK_M5_USER_FAULT_RECOVER`; default M3 and legacy M5-D1 IDT DPL0 are untouched. The pure frame validator requires error code zero and a trusted user CS/SS, RIP, RSP and active CR3; #DB/#BP are trap-class so their saved RIP may be **exactly one byte past the last code byte**, but must not exceed it. #DE and other fault-class traps still demand RIP inside the loaded executable's declared bounds. In [native QEMU proof](../scripts/test_m5_user_trap_containment.py) the recovered CPU delivers six faults/traps (#DE, #DB×2, #BP×2, #UD), each followed by real `run /apps/hello.hke` and six-frame owner reuse; repeated on two non-timer and two active-x2APIC boots. The test compiles a one-byte ICEBP and one-byte INT3 into separate HKEX files to validate real boundary RIP, then independently confirms default legacy DPL0/fail-stop behavior for all three new vectors. **PR/CI/merge for this new slice are separate future checks.** This does not authorize kernel-mode traps to return or allow arbitrary code to execute safely.
- **M5-E3-C complementary regression (feature branch):** A new two-byte `INT $3` executable ending *exactly* at the last code byte now exercises the architectural DPL3 vector-3 trap and postinstruction code-end RIP, in addition to the previously proven one-byte INT3 and ICEBP last-byte cases. Four real QEMU boots (two E1/no timer and two E2/live x2APIC) now execute seven CPU traps and seven healthy loaded-program re-runs per boot. The separate E3 mixed syscall/timer/fault stress now includes seven CPU faults while preserving its seven successful programs, two real timer timeouts, and two invalid syscall exits per QEMU boot. This extension changes **tests and docs only**; it does not claim new kernel runtime functionality. Local QEMU PASS, exact new PR-head CI/merge pending.
- Host UBSan `-O0/-O3` tests reject forged kernel CS/SS, wrong CR3, corrupted RFLAGS, invalid RIP/RSP, too-large images and invalid #PF/other exception codes before entering the guest.

## Limits and phase separation

This exact M5-E1 flag set (without `--user-timeout`) still lacks a CPU execution budget: a nonyielding CPL3 program can hang its shell. **M5-E2 now implements an independent, opt-in real x2APIC budget** via `--user-fault-recover --user-timeout`, verified in native QEMU and merged in PR #79. The new M5-E3-B #DE/#DB/#BP CPU trap protection works in both configurations, but its PR/CI must be independently checked. No general syscall input pointer checking, multi-program concurrency, user FPU/FS/GS/SMP context, ELF loader, writable disks, USB keyboards, calibrated APIC timer, UEFI, physical hardware or strong security boundary. FNV checksum is not an authenticity mechanism; run only trusted compile-time programs. Kernel-origin and unarmed faults are fail-stop, not repaired. M5-E2 and M5-E3 acceptance are tracked in [Issue #75](https://github.com/Eun-si123/html-kernel-os/issues/75).
