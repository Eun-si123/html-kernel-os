AN OPEN EXPERIMENT IN SYSTEMS PROGRAMMING

HTML로 쓴 코드가
커널을 부팅한다.

웹페이지를 운영체제처럼 꾸미는 프로젝트가 아니야. HTML 형태의 새 언어를 네이티브 코드로 컴파일해 실제 x86-64 커널을 부팅하는 실험이야.

01 — THE APPROACH

마크업에서
머신 코드까지.

HTML의 익숙한 태그 구조를 가져오되, 목적은 화면 표시가 아니라 실행이야. 이미 구현된 것과 앞으로 구현할 것을 분리해 공개하고 있어.

01 / WRITE

언어를 작성한다

<kernel>과 <onboot>부터 시작해, 현재는 정수 자료형·함수·조건문·반복문도 사용할 수 있어.

02 / COMPILE

네이티브 코드로 바꾼다

컴파일러가 문법과 타입을 검증해 C 코드를 생성하고, GCC와 Limine으로 x86-64 부팅 이미지를 만들어.

03 / VERIFY

부팅으로 확인한다

QEMU와 브라우저 에뮬레이터가 실제 ISO를 실행해. 소스를 바꾸면 출력도 바뀌는지 자동으로 검증해.

02 — SOURCE / OUTPUT

코드가 가장 정확한 설명이다.

실제 HTML 형태의 커널 소스와 C 출력 방식의 개념적 일부를 비교해 봐. 코드는 읽기 전용이고, 실행은 부팅 체험실에서 가능해.

READ-ONLY PREVIEW 
<kernel arch="x86_64">
  <onboot>
    <print>Hello from HTML Kernel!</print>
    <print>Native code, not a browser.</print>
    <halt/>
  </onboot>
</kernel>
/* Illustrative outline, not exact generated C */
static inline void outb(unsigned char value) {
  __asm__ volatile ("outb %0, %1" :
    : "a"(value), "Nd"((unsigned short)0xE9));
}
void kernel_main(void) {
  /* Compiler-generated output bytes on 0xE9 / COM1 */
  __asm__ volatile ("cli");
  for (;;) __asm__ volatile ("hlt");
}
COM1 + debugcon 0xE9 / C outline은 설명용 발췌

검증 범위 — HTML형 소스의 실제 x86-64 컴파일·QEMU 부팅 외에도 제한된 ROMFS, 시리얼 명령 입력, 보호된 Ring 3 사용자 프로그램 실행과 메모리 회수를 검증했어. 공개 M5 웹 실행실에서도 Chromium으로 네이티브 사용자 프로그램 2회 실행·종료 코드 7·메모리 회수를 직접 확인했어. 다만 범용 앱 실행, 임의 코드 보안 격리, 쓰기 가능한 디스크, 실기기 부팅은 아직 구현·검증되지 않았어.

03 — DEVELOPMENT RECORD

어디까지 작동하나.

작동하는 기능, 진행 중인 언어 확장, 아직 없는 운영체제 기능을 정확히 구분해. 전체 M0–M6 로드맵 ↗

M0

파서와 네이티브 코드 생성

HTML 형태의 제한된 구문을 검증하고 x86-64 오브젝트를 생성

구현됨
M1

실제 커널 부팅

Limine ISO 생성, QEMU BIOS 및 Chromium 기반 웹 부팅 검증

검증됨
M2

프로그래밍 언어 확장

정수 4종, 함수, 조건문, 반복문, 비트 연산 구현. 모듈·자료구조는 진행 중

부분 구현
M3

메모리·CPU 예외

4KiB 페이지 할당, 사유 CR3, #PF/#GP 복구 실험과 소유권 검증을 실제 QEMU에서 확인

제한적 검증

스케줄링·Ring 3 격리

제한된 단일 CPU 환경에서 타이머 인터럽트, 사용자·커널 권한 분리 및 오류 격리 검증

범위 한정 구현
M5

ROMFS, COM1 명령, 별도 실행 파일 로딩·64비트 출력·종료 코드·프레임 회수. 실제 브라우저 실행 보기 ↗
